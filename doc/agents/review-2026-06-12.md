# minting-rails Code Review — 2026-06-12

## Clarity: Good, with minor friction points

**What works well:**

- `money_attribute :price` / `money_attribute :price, currency: 'USD'` — the API surface is clean and intuitive
- Two modes (single-column via AR type, composite via `composed_of`) are clearly delineated by whether the column name matches
- Parser handles `Numeric`, `String`, `Mint::Money`, and `nil` consistently
- `with_mint_config` test helper is well-designed for state isolation
- File structure is logical: `lib/minting/money_attribute/` groups related concerns

**What could be clearer:**

1. **`money_type.rb:51-53`** — Double-nested `ActiveSupport.on_load(:active_record)`:
   ```ruby
   ActiveSupport.on_load(:active_record) do
     ActiveSupport.on_load(:active_record) { include Mint::MoneyAttribute }
     ActiveRecord::Type.register(:mint_money, Mint::MintMoneyType)
   end
   ```
   The inner `on_load` is dead code; the outer block already runs when AR loads. Simplify to a single level.

2. **`find_money_attributes` error** (`money_attribute.rb:50`) — "Could not find attributes to map to..." doesn't say *which* columns were expected vs found. This makes debugging harder for users.

3. **`rails_test.rb:27-28` asserts `CRC`/`NGN`**, but the dummy app's initializer registers `CRCA`/`NGNA` (with an `A` suffix). The tests pass because `CRC`/`NGN` are natively in the minting gem, but the mismatch is confusing to anyone reading the code alongside the test.

4. **`railties.rb:9`** uses `config.to_prepare` — this fires on every request in development. Currency registration should use `config.after_initialize` or `config.before_initialize` instead (runs once at boot).

## Usefulness: High

**Strengths:**

- Solves a real problem — wiring money objects into ActiveRecord attributes is boilerplate-heavy; this gem eliminates it
- Two coverage modes — single-column (fixed currency, simple schema) and composite (multi-currency, natural for legacy schemas) address different real-world needs
- Custom mapping (`mapping: {amount: :foo, currency: :bar}`) makes it work with pre-existing column names
- Column-type awareness (`amount_extractor_for`) correctly switches between `:fractional` (integer) and `:to_d` (decimal), handling a common gotcha automatically
- Railtie auto-registration — custom currencies declared in the initializer get registered at boot without the user needing to call `Mint.register_currency`
- Generator ships with a well-commented initializer template
- Test coverage is good — 13 tests across 3 files covering both modes, serialization, nil, edge cases, and configuration

**What's missing or could go further:**

- **Stub test** (`test/dummy/test/models/simple_offer_test.rb`) is just a comment — delete it
- **Version mismatch** — `version.rb` says `0.7.1` but `rake build` labels it `0.7.0` (stale build artifact). Worth aligning.
- **No fallback for `mapping:` with only one key** — passing `mapping: {amount: :foo}` (missing currency) produces a confusing `ArgumentError`. The validation catches it, but the error message could name the missing key.
- **`Numeric#dollars`/`#euros`** in `core_ext.rb` is convenient but risks gem conflicts. Standard money gems do the same trade-off, so it's a minor concern.
